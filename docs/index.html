A working proof of concept for Moonshot (YC S26)

Earshot(in ear)

Samantha hears the whole day. Earshot is the layer that decides which words were promises, whose promises they were, what is too private to keep, and when it is polite to speak.

Built by Khushi Singhal. Python, no dependencies, 38 tests. Code: github.com/khushisinghal21/earshot

Scorecard

Three hand-labelled days replayed through a keyword baseline and through Earshot. Days 1 and 2 were used while building. Day 3 was written and labelled first, then run once, untuned.

What the held-out day shows

The guardrails are structural, so they held. The misses are all language understanding, which is where a model belongs. The repo has a model-backed extractor where the model proposes ledger changes and code enforces who said it and quotes the evidence.

Pronouns that point backwards

can you handle it this time? means the wifi bill from the sentence before. Rules filed "handle it this time".

Promises without "I'll"

Need to remember to renew my passport and Sure, will do to a request with no "can you" were both missed.

Paraphrased closure

Collected the order and Kitchen's clean didn't close their loops, so one whisper reminded about a bill already paid.

A wrong memory

send me the photos from Neha's wedding was stored as a fact about Neha. Privacy held, but precision didn't.

Replay a day

How the timing works: the arbiter is causal. It knows who is talking right now and what has already been transcribed, never when the next person will start, so collisions are measured after the fact, the way they would happen in someone's ear.

Transcripts are synthetic and speaker labels are given, standing in for diarization and voiceprints. Run it yourself with python -m earshot eval.
